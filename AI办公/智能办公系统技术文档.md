## 项目背景
多Agent项目实战：小滴智能OA办公审核AI系统

**项目简介**
小滴智能OA是一个基于LangGraph构建的对话式OA办公系统，通过自然语言交互完成请假申请、审批、查询等日常办公流程。

**核心功能**
- ✅ 智能对话：自然语言交互，无需学习复杂界面
- ✅ 请假申请：自动识别请假意图、收集信息、提交申请
- ✅ 审批流程：主管可查看待审批申请、给出决策和意见
- ✅ 查询功能：查询我的申请、查询待审批事项
- ✅ RAG增强：内置反思补搜工作流，生成专业审批建议
- ✅ 联网搜索：集成Tavily，支持实时联网搜索
- ✅ 多轮对话：基于Redis的会话记忆机制

## Agent 工作流程
### 1. 对话主流程 (chat_agent.py)
这是系统的核心工作流，处理所有用户对话：
```
用户消息
    ↓
[START] → intent_recognition (意图识别) → search (联网搜索) → task_router (任务路由) → task_executor (任务执行)
                                                                                              ↓
                                                                                         条件路由
                                                                                   ┌────────┴────────┐
                                                                                   ↓                 ↓
                                                                          submit_leave          general_chat
                                                                          (提交请假)            (日常对话)
                                                                                   ↓                 ↓
                                                                           query_status        get_suggestion
                                                                           (查询状态)          (获取建议)
                                                                                   ↓                 ↓
                                                                          query_pending           [更多...]
                                                                          (查询待办)          (审批/删除等)
                                                                                   ↓                 ↓
                                                                          response_generator ←──────┘
                                                                          (回复生成)
                                                                                   ↓
                                                                                 [END]
```

### 2. 反思补搜流程 (reflection_search.py)
用于生成高质量的审批建议：
```
申请信息 → generate (初步建议)
                   ↓
              evaluate (自我评估)
                   ↓
         ┌─────────┴─────────┐
         ↓                   ↓
    需要补充           建议充分
         ↓                   ↓
      search (补搜)     output (最终建议)
         ↓
     regenerate (优化建议)
         ↓
    evaluate (再次评估)
```

## 关键代码解析
### 1. 对话状态定义 chat_state.py
```python
from typing import TypedDict, List, Annotated
from langgraph.graph import add_messages

class ChatState(TypedDict):
    messages: Annotated[List[dict], add_messages]  # 对话消息历史 (自动追加!)
    user_message: str                    # 用户当前消息
    intent: str                          # 识别的意图
    extracted_info: dict                 # 提取的关键信息
    current_task: str                    # 当前任务类型
    task_result: str                     # 任务执行结果
    response: str                        # AI响应
    conversation_context: dict           # 对话上下文
    needs_search: bool                   # 是否需要联网搜索
    search_results: str                  # 搜索结果
    iteration_count: int                 # 循环迭代次数（防止无限循环）
```

核心设计：
- `Annotated[List[dict], add_messages]` 是关键！它告诉LangGraph，当多个节点返回新消息时，自动追加而不是覆盖
- 每个字段有明确的语义职责，避免过度耦合

### 2. 主图构建 chat_agent.py
```python
from langgraph.graph import StateGraph
from langchain_openai import ChatOpenAI
from langgraph.checkpoint.redis import RedisSaver
from langgraph.store.redis import RedisStore
from common.redis_client import get_redis_client

def create_chat_graph(redis_url: str):
    # 初始化 LLM
    llm = ChatOpenAI(model="qwen3.5-plus", temperature=0.7)

    # 创建所有节点 (由工厂函数统一管理)
    nodes = create_all_nodes(llm, tavily_api_key)

    # 初始化 Redis 连接 (用于 Checkpoint 和 Store)
    redis_client = get_redis_client()
    store = RedisStore(redis_client)
    checkpointer = RedisSaver(redis_client=redis_client)

    # 构建 StateGraph
    builder = StateGraph(ChatState)

    # 注册节点
    for node_name, node_func in nodes.items():
        if node_name != "route_task_execution":
            builder.add_node(node_name, node_func)

    # 配置边和路由
    builder.add_edge("intent_recognition", "search")
    builder.add_edge("search", "task_router")
    builder.add_edge("task_router", "task_executor")

    # 条件边：根据任务类型决定下一跳
    route_func = nodes["route_task_execution"]
    builder.add_conditional_edges(
        "task_executor",
        route_func,
        {
            "submit_leave": "submit_leave",
            "approve_application": "approve",
            "query": "query",
            "query_pending": "query_pending",
            "delete_application": "delete",
            "suggestion": "suggestion",
            "general_chat": "general_chat"
        }
    )

    # 所有子节点最终汇集到 response_generator
    builder.add_edge("submit_leave", "response_generator")
    builder.add_edge("approve", "response_generator")
    builder.add_edge("query", "response_generator")
    builder.add_edge("query_pending", "response_generator")
    builder.add_edge("delete", "response_generator")
    builder.add_edge("suggestion", "response_generator")
    builder.add_edge("general_chat", "response_generator")

    # 设置入口点并编译
    builder.set_entry_point("intent_recognition")
    graph = builder.compile(checkpointer=checkpointer, store=store)

    return graph, store
```

设计亮点：
- 使用工厂函数 `create_all_nodes()` 统一节点创建
- Redis同时承担 Checkpoint（对话历史）和 Store（共享知识）两个角色
- 条件路由让流程更灵活，易于扩展新业务

### 3. 意图识别节点 chat_nodes/recognition.py
```python
import re
import json

def intent_recognition_node(state: ChatState):
    # 1. 获取当前消息和历史
    user_message = state.get("user_message", "")
    messages = state.get("messages", [])

    # 2. 拼接待识别提示词
    prompt = f"""你是一个OA系统智能助手，请识别用户的意图。
    意图选项：
    - submit_leave: 提交请假申请
    - delete_application: 删除申请
    - approve: 审批操作
    - query_status: 查询申请状态
    - query_pending: 查询待办事项
    - get_suggestion: 获取审批建议
    - general_chat: 日常对话
    - needs_search: 需要联网搜索的问题

    提取关键信息（如果有）。
    请以JSON格式返回：{{"intent": "...", "extracted_info": {{...}}, "needs_search": true/false}}
    """

    # 3. 调用LLM解析
    response = llm.invoke(prompt)
    json_match = re.search(r'\{.*\}', response.content, re.DOTALL)
    result = json.loads(json_match.group())

    return {
        "intent": result.get("intent", "general_chat"),
        "extracted_info": result.get("extracted_info", {}),
        "needs_search": result.get("needs_search", False)
    }
```

关键设计：
- 自然语言 + JSON 输出，适合 LLM 处理
- 优先级设计：确认提交 > 明确操作 > 日常对话
- 内置日期解析逻辑（"周X"转具体日期）

### 5. 对话路由 chat.py
```python
import json
import uuid
import asyncio
from datetime import datetime
from fastapi import APIRouter, Depends
from fastapi.responses import StreamingResponse

router = APIRouter()

@router.post("/chat/stream")
async def chat_stream(request: dict, current_user: dict = Depends(get_current_user)):
    graph = get_chat_graph()
    thread_id = request.get("thread_id", str(uuid.uuid4()))
    user_message = request.get("user_message", "")

    async def event_generator():
        # 构建初始状态
        initial_state = {
            "messages": [{
                "role": "user",
                "content": user_message,
                "timestamp": datetime.now().isoformat()
            }],
            "user_message": user_message,
            "intent": "",
            "conversation_context": {
                "user_id": current_user.get("username"),
                "user_role": current_user.get("role"),
                "user_department": current_user.get("department")
            }
        }
        config = {"configurable": {"thread_id": thread_id}}

        # 执行工作流 (线程池包装，避免阻塞事件循环)
        result = await asyncio.to_thread(graph.invoke, initial_state, config)

        # 打字机效果逐字符发送
        response_text = result.get("response", "")
        for i in range(0, len(response_text), 3):
            chunk = response_text[i:i+3]
            yield f"event: token\ndata: {json.dumps({'token': chunk})}\n\n"
            await asyncio.sleep(0.02)

        # 完成事件
        yield f"event: complete\ndata: {json.dumps({'thread_id': thread_id, 'response': response_text})}\n\n"

        # 更新会话元数据
        redis_client.hset(metadata_key, thread_id, json.dumps({"time":datetime.now().isoformat()}))

    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
    )
```

核心技术：
- 使用 `thread_id` 实现会话隔离和历史恢复
- SSE 流式输出，提供打字机效果
- 使用 `asyncio.to_thread()` 避免阻塞 FastAPI 事件循环
- 自动管理会话元数据（Redis Hash）

## 会话隔离机制
实现原理：系统通过 **三层隔离** 确保不同用户、不同会话的数据安全

|隔离层级|字段|作用|存储位置|
|---|---|---|---|
|1|tenant_id|业务租户隔离（预留设计）|业务表字段|
|2|user_id|用户隔离|业务表字段 / Redis key前缀|
|3|thread_id|会话隔离|LangGraph Checkpoint key|

**Redis Key 设计**
```
# 会话元数据 Hash
session_metadata:{user_id}
  ├─ {thread_id1} → {json}
  ├─ {thread_id2} → {json}
  └─ ...

# LangGraph Checkpoint (由 RedisSaver 自动管理)
checkpoint:{thread_id}:{checkpoint_id}
  └─ 完整状态备份
```

Checkpoint 删除接口
```python
from fastapi import APIRouter, Depends

@router.delete("/chat/session/{thread_id}")
async def delete_chat_session(thread_id: str, current_user: dict):
    # 1. 删除业务元数据
    redis_client.hdel(f"session_metadata:{current_user['username']}", thread_id)

    # 2. 使用 LangGraph 官方方法删除所有 Checkpoint
    graph = get_chat_graph()
    if hasattr(graph, 'checkpointer'):
        graph.checkpointer.delete_thread(thread_id)
```
